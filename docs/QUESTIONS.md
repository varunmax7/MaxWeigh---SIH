# Tula — open questions

record it here, continue (implementation.md §0). Resolve with the human owner between
phases.

| 16 | P2 | §6.2's `action()` pipeline is written as one linear chain — "Zod parse → session → permission → **lab scope** → transaction(handler + audit)" — but the wrapper cannot know which lab an arbitrary action touches until the handler has looked up the target entity (e.g. an evaluation's `lab_id`). | `ctx.assertLabAccess(labId)` is handed to the handler (inside the transaction) instead of being a fixed pre-check: the handler calls it once it has resolved the entity's lab, and it throws `ActionError('FORBIDDEN', …)` unless the acting user is a member of that lab (`lab_members`).
